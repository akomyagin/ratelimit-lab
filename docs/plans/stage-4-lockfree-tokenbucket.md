## Два подводных камня, оплаченных предыдущими этапами

Оба стоили реальной отладки на Этапах 2–3 — не переоткрывать.

**1. Сравнение допуска писать сразу с `admitEpsilon`.** Все лимитеры хранят
состояние накопительным `float64`. Строгое сравнение даёт измеримый недобор:
клиент на настроенной скорости с не-двоично-точным шагом (`rate` 1/с, опрос
каждые 100 мс) после слива целой единицы оставляет остаток ~1.4e-16, каждый
граничный запрос денаится — **910 допусков вместо 1000, ~9% недобора**,
замерено и в token bucket, и в leaky bucket. Константа `admitEpsilon = 1e-9`
живёт в `internal/limiter/limiter.go` и общая для всех реализаций. Её граница
применимости: при лимите от 2^24 шаг `float64` равен 3.7e-9, `capacity+1e-9 ==
capacity`, и эпсилон молча становится no-op — осознанно не чинится
относительным эпсилоном, лимиты проекта считают запросы, а не байты.

**2. Тест на дрейф — с не-двоично-точным шагом.** Табличные тесты с двоично
точными `rate`/шагом этот дефект **не ловят**: он проходит мимо них целиком.
Нужен отдельный кейс по образцу `TestLeakyBucket_SteadyStateNonBinaryExactStep`
в `internal/limiter/leakybucket_test.go`.

## Счётчики в стресс-тестах

`SKILL.md` §5 (после #7) запрещает не только `int` под mutex, но и обходной
вариант «копить в локальной переменной, слить один раз после цикла». Причина
не стилистическая: в стресс-тесте лимитера contention и есть предмет измерения,
локальное накопление снимает с горутин ровно то давление на общее состояние,
ради которого тест написан, и тем сильнее, чем больше `callsPer`. Считать
`allowed.Add(1)` на каждый допуск.

Мотив записать это отдельно: паттерн уже копировался из теста в тест — так были
написаны все три `*_ConcurrentNoOverAdmit` до #5. В Этапе 4 стресс-тесты новые,
соблазн вернётся.

## Открытые решения (за автором, не за планировщиком)

- **Упаковка состояния:** `atomic.Pointer[state]` на неизменяемый снапшот
  **или** битовые поля в одном `uint64`. Плюсы/минусы зафиксировать при
  реализации в комментарии/коммите.
- **Backoff при неудачном CAS** — SKILL §5 намеренно не предписывает стратегию.

## Критерий готовности

Из `TECHNICAL_PLAN.md`: стресс-тест стабильно зелёный под `-race` с `-count>1`
и `GOMAXPROCS>1`, инвариант «суммарно разрешённых ≤ `capacity`» не нарушается.
Плюс общий гейт проекта: `go build ./... && go vet ./... && go test -race ./...`
чисто, `gofmt -l .` пусто.

## Режим работы

Полный пайплайн (новый Этап, центральный конкурентный код): планировщик →
кодер → параллельно тесты и независимое ревью → разбор находок → финальный
прогон в основной сессии → commit/push/PR в `master`. Ревьюеру ставить промпт
на полноту («сообщи всё, что нашёл, с уверенностью и критичностью»), отсев
делает основная сессия.
